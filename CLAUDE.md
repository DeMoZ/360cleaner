# 360Cleaner

Убирает фотографа и людей с 360° панорамы (equirectangular 2:1) по кадрам с одной точки и сохраняет её в нужном
размере и качестве. Без нейросетей — кроме отдельного режима ИИ-дорисовки (`inpaint.rs`), выключенного по
умолчанию. Режим — по числу фото: 1 — только пересохранение, 2 — фотограф (две зоны), 3+ — прохожие (медиана).
Отвечай пользователю по-русски. Описание для пользователя — [README.md](README.md) (английский), [README.ru.md](README.ru.md), [README.th.md](README.th.md):
меняешь одно — поправь все три.

## Устройство

Rust (edition 2024) + tao 0.37 / wry 0.57 (системный WebView: WKWebView на Mac, WebView2 в Windows) + Rayon.
Интерфейс — один файл `src/ui/index.html` (HTML/CSS/JS, встраивается через `include_str!`).

- `main.rs` — окно, обмен с WebView, состояние (`State` под `Mutex`, список `photos` до `MAX_PHOTOS`), загрузка
  фото (`LOADERS` потоков), рабочий поток расчёта, диалог сохранения, донаты и обновления.
- `processor.rs` — обработка. Два кадра: разница ΔE в Lab → порог (сам поднимается, пока до расширения отличий
  больше `MAX_RAW_CHANGED`) → открытие (убирает точки шума) → расширение кругом → два угловых кластера на окружности
  по маске сильных различий (`CORE_THRESHOLD`, `CORE_OPEN`) → границы зон подальше от людей (`emptiest_cut`) →
  мягкая маска `Alpha` → смешивание. Три и больше
  (`compute_stack_preview`): медиана кадров = фон → маска отличий каждого кадра от фона → в каждой точке первый
  чистый кадр → смягчённые доли кадров → маски для смешивания по очереди (`blend_sequence`).
- `export.rs` — сохранение: кадры уменьшаются до размера результата (`fast_image_resize`, Lanczos3), смешиваются по
  маскам превью, JPEG через `jpeg-encoder` (оптимизированные таблицы, прогрессивный, 4:2:0, от q95 — 4:4:4).
- `cubemap.rs` — кубическая карта из панорамы (бикубическая выборка по направлению взгляда): грани
  `_f _r _b _l _u _d`, полоса 6×1 в порядке Unity (+X −X +Y −Y +Z −Z), крест 4×3. Формат сохранения —
  `export::Format` (в настройках и окне строкой: `equirect`, `cube`, `strip`, `cross`). Граням не пишется XMP
  (`xmp::without_xmp`): с GPano просмотрщики приняли бы квадрат за сферу.
- `inpaint.rs` — ИИ-дорисовка (отдельный режим, настройка `aiFill`, по умолчанию выключен): кисть в окне → мазки
  `Dab` → маска превью → по каждому связному куску вид с перспективой 512×512 в его сторону (`View`) → модель LaMa
  (`lama_fp32.onnx` из Carve/LaMa-ONNX, закреплён коммит и SHA-256, скачивается в кэш при включении) через `ort`
  (ONNX Runtime вшит статически) → `Patch` переносится обратно. Дорисовывается по результату, склеенному до 8K
  (`export::compose`); при сохранении куски только переносятся на полный размер, как маски `Alpha`. Имя файла — с
  `_ai`, в окне дорисованное отмечено. После дорисовки окно показывает склеенный результат в 4K
  (`AI_VIEW_WIDTH`), а не превью 1400: при увеличении превью идёт квадратиками, и заливка казалась грубее, чем в
  файле. Значок в шапке «No AI» меняется на «AI fill», пока режим включён.
- `i18n.rs` — выбор языка и строки системных диалогов; тексты окна — `ui/i18n.js`.
- `xmp.rs` — перенос APP1 (EXIF, XMP GPano) и APP2 (ICC) из первого фото в результат (после JFIF);
  `scale_gpano` пересчитывает размеры GPano при уменьшении (иначе просмотрщики 360° ломаются).
- `update.rs`, `donations.rs`, `net.rs`, `settings.rs` — как в AdbToolsGUI (см. ниже).

## Важно (на этом уже обожглись)

- **WebView живёт только в главном потоке.** Из рабочих потоков в окно — только через `Ui::send` →
  `EventLoopProxy` → `UserEvent::Js` → `evaluate_script` в цикле событий. Первая версия держала WebView в
  `thread_local` и звала его из рабочих потоков: там он пустой, и ни одно сообщение до окна не доходило.
- **Диалоги `rfd` — только в главном потоке** (на Mac иначе нельзя): IPC шлёт `UserEvent::PickFile` / `Save`.
- **Расчёт превью — один рабочий поток**: из очереди берётся последний запрос, результат сверяется с
  `State::generation` и выбрасывается, если фото или параметры успели поменяться.
- **Экспорт не пересчитывает маску в полном размере**, а растягивает `Alpha` превью (`blend_into`): файл совпадает
  с превью, и это быстро. Прежняя дилатация перебором на 8K с радиусом ×6 работала бы часами.
- **В памяти при экспорте только два кадра полного размера** (16K — 360 МБ каждый): кадры смешиваются по очереди,
  маски `sequential_alphas` подобраны так, что итог равен взвешенной сумме долей. Кадр без доли не открывается.
- Встроенный `JpegEncoder` из `image` — только для превью: он пишет 4:4:4 без оптимизации таблиц, файл в 2–3 раза
  тяжелее. Замер веса на настоящей панораме: `CLEANER360_SAMPLE=photo.jpg cargo test --release -- --ignored
  --nocapture save_sizes`.
- Расширение маски — `dilate_mask_360` за O(w·h·r) через расстояния по строкам; тест сверяет с перебором.
- **Зоны двух кадров не искать по расширенной маске и не делить посередине.** При низком пороге шум и разница
  экспозиции покрывают полкадра, центры зон уезжают, и граница резала человека пополам (пара 0007/0008, порог 5:
  человек остался, пришлось чистить второй раз). Доля различий после расширения зависит от ползунка расширения и
  для автоподъёма порога не годится. Проверка на 9 настоящих парах × 21 сочетание порога/расширения: было 140/189
  верных разбиений, стало 189/189.
- **ONNX Runtime — только на процессоре** (`AutoDevicePolicy::PreferCPU`). Готовая сборка `ort` для Mac есть лишь с
  CoreML, и он включался сам: модель перестраивалась при каждой загрузке 30–150 с и считала медленнее (8 с против 3).
- **Вид для дорисовки — от размера места** (`HOLE` = 0.7 половины вида), не «поле зрения × запас»: у перспективы
  140° центр сжат, человек вплотную к камере занимал 120 точек из 512, и заливка шла «кубиками».
- ONNX Runtime собран под macOS 13.4: `.cargo/config.toml` ставит `MACOSX_DEPLOYMENT_TARGET`, в Info.plist —
  `LSMinimumSystemVersion` 13.4. Тесты в `--release` без `libclang_rt.osx.a` (подключает `build.rs`) не линкуются.
  Обновление из программы старую копию возвращает, только если не удалось заменить файлы; если новая версия просто
  не запускается (старая macOS), старой уже нет — поэтому подъём минимальной версии системы — предупреждение в
  заметках к релизу (их видно в окне обновления до установки).
- Проверка на настоящей модели: `CLEANER360_LAMA=lama_fp32.onnx cargo test --release -- --ignored --nocapture
  lama_runs` (и `lama_photo` для своего фото).
- Удалённые Python-версии (PySide6 / OpenCV) лежат в истории git до коммита cd6040a, не возвращай их.

## Донаты и обновления

- Донаты: файл `360cleaner.json` из `DeMoZ/donations` (raw.githubusercontent → jsDelivr → кэш → копия
  `assets/donations.json`), формат schema 1 как в AdbToolsGUI / EnhanceCapCut / UniversalKM. Ссылки меняются в
  репозитории donations; копию в `assets/` держать такой же.
- Обновления (`update.rs`): GitHub API `releases/latest` репозитория `DeMoZ/360cleaner`, архив
  `360Cleaner-<v>-macos-arm64.zip` (`360Cleaner.app`, упакован `ditto`) или `360Cleaner-<v>-windows-x64.zip`
  (`360Cleaner.exe`), проверка SHA-256 из поля `digest`, замена скриптом после выхода, перезапуск; при неудаче
  старая копия стартует с `--update-failed`. В сборке `cargo run` (debug) обновление выключено.
  Адрес API можно подменить переменной `CLEANER360_UPDATES_URL`.
- Сеть — системный `curl`, ссылки открываются только `https://`.

## Проверки и релиз

- `cargo test` (медленный замер: `cargo test --release -- --ignored --nocapture timings`),
  `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` — CI требует всё это.
- Windows с Mac: `cargo check --target x86_64-pc-windows-msvc`. На настоящей Windows программа не проверялась.
- Сборка Mac: `scripts/build-macos.sh` (только Apple Silicon). Значок: `scripts/make-icon.sh` → `assets/`.
- Релиз: `version` в `Cargo.toml` + `docs/releases/v<версия>.md` + тег `v<версия>` на main (CI сверяет тег с
  версией и выкладывает .dmg и Mac .zip). Windows .zip — только по явной просьбе: переменная репозитория
  `RELEASE_WINDOWS=true` (`gh variable set` до тега, `gh variable delete` после); без неё Windows в CI только
  проходит тесты и clippy, а в заметках к релизу раздела Windows нет.
- Языки (`i18n.rs`, `ui/i18n.js`): en, ru, es, pt, de, fr, zh, ja; язык системы через `sys-locale`, иначе en;
  выбор в настройке `language` (пусто — системный). Все тексты окна — в словаре `I18N` (`ui/i18n.js`, Rust
  подставляет его в страницу вместо `/*I18N*/`). Rust шлёт в окно ключи (`ui.status("stLoading", json!{…})`),
  а не готовые фразы; технические подробности ошибок (curl, файлы) — по-английски. Строки системных диалогов
  `rfd` — в `i18n::tr`. Новый ключ — сразу во все 8 языков: `node scripts/check-i18n.mjs` (в CI) проверяет набор
  ключей и параметров `{…}`. Тексты доната — во всех 8 языках в `360cleaner.json` и `assets/donations.json`.
- Заметки к релизу (`docs/releases/`) — по-английски и по-русски: их показывает окно обновления.
